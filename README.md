# RP Stealth Security (v10.0.1)

**Webシステム向け「能動的欺瞞（Active Deception）」リバースプロキシ＆ミドルウェア**

不正アクセスを「403 Forbidden」等のエラーで遮断（門前払い）する代わりに、正常応答（`200 OK`）と無害なダミーデータ（空の金庫）を返却することで、攻撃者や自動探索AIに防御の存在を悟らせず隔離・無力化する次世代セキュリティアーキテクチャです。

---

## 1. アーキテクチャの特徴と導入メリット

従来の境界防御（WAF・IP遮断）では、エラー応答そのものが攻撃者に対して「防御壁が存在し、別の侵入口を探すべきである」というフィードバックを与えていました。本ソフトウェアは、通信の文脈と振る舞いを多層解析し、異常と判定された通信のみを欺瞞（Deception）ルートへ静かにルーティングします。

* **正常応答偽装（`200 OK` Stealth Deception）**
  * 異常プローブや脆弱性スキャンを検知した際、エラーコードを返さず `200 OK` と無害なダミーペイロード（JSON / HTML / ダミー資料）を返却します。
* **外部ファイル共有リンク防御モジュール（`ShareDeceptionMiddleware` / v10.0.1新機能）**
  * 共有URLやドキュメント配信エンドポイントに対し、許可されていないネットワーク・端末指紋・異常な列挙クエリからのアクセスを検知した場合、本物データを隔離したまま閲覧専用の無害なダミー資料データを返却し、アクセス痕跡を即座に記録します。
* **ソケット遅延（Tarpit）およびフォレンジック記録**
  * 自動化されたスキャンボットによる連続リクエストの探索効率を低下させる応答遅延処理と、インシデント調査に必要なアクセスログ記録機能を備えています。
* **言語・環境非依存のリバースプロキシ導入（既存コード改修不要）**
  * 既存Webシステムの前段（ポート80/443）に独立したリバースプロキシ型Dockerコンテナとして配置できるため、バックエンドの言語（Java、PHP、Go、Node.js、.NET、レガシーシステム等）を問わず、既存ソースコードの改修なしで導入可能です。また、Python（FastAPI等）環境へミドルウェアとして直接組み込む構成にも対応しています。

## 2. 最短導入ステップ（Dockerリバースプロキシ利用）

サーバー上で以下のコマンドを実行することで、既存Webシステム（例：`127.0.0.1:8080`）の前段に迎撃プロキシが起動します。

```bash
docker run -d \
  --name rp-stealth-shield \
  --restart always \
  -p 80:80 -p 443:443 \
  -e BACKEND_URL="http://127.0.0.1:8080" \
  -e LICENSE_KEY="RP9-YOUR-PURCHASED-KEY" \
  rp-holdings/rp-stealth-security:10.0.1
```

### Python（FastAPI）ミドルウェアとしての組み込み例

```python
from fastapi import FastAPI
from rp_stealth_security import StealthMiddleware, ShareDeceptionMiddleware

app = FastAPI()

# 基本の能動的欺瞞ミドルウェア
app.add_middleware(StealthMiddleware)

# 共有リンク・ドキュメント配信エンドポイント向け欺瞞保護（v10.0.0）
app.add_middleware(
    ShareDeceptionMiddleware,
    protected_prefixes=["/share/", "/docs/"],
    whitelist_ips=["10.0.0.0/8", "192.168.0.0/16"],
)
```

## 3. 可用性・法規準拠を担保する4つの設計原則

従来のセキュリティツール導入において最大の懸念となるのは、「誤検知による正規通信の遮断（業務停止リスク）」や「ミドルウェアの不具合・高負荷によるシステム障害」です。RP Stealth Security は、システムの可用性とコンプライアンスを最優先するため、以下の設計原則に基づいて実装されています。

1. **フェイルオープン（Fail-Open）アーキテクチャの実装**
   * ミドルウェア内部で万一の例外処理、パース失敗、メモリ圧迫、ライセンス検証エラー等が発生した場合でも、正規のHTTPリクエストをエラー（500/403）で遮断せず、直ちにバイパス（素通り）させてバックエンドへ通信を引き渡す設計を採用しています。
2. **誤検知（False Positive）による一律遮断の回避**
   * 従来型WAFのように閾値を超えた通信を即座にドロップ（接続拒否）するのではなく、異常なプローブやスキャンパターンを検知した通信に対してのみ「ダミー応答」をルーティングします。これにより、意図しない誤検知が発生した場合でもシステム全体のアクセス不能状態を回避します。
3. **ハックバック（逆侵入）非実施の法規準拠設計**
   * 不正アクセス元への逆攻撃・端末操作・マルウェア送付等の能動的反撃処理は一切実装しておらず、日本国内の不正アクセス禁止法および各国サイバー関連法規に準拠した「自己防衛・欺瞞隔離」のみを行います。
4. **ペイロード非保存・エッジ完結プライバシー設計**
   * 保護対象システムを通過する業務データ・共有ファイルの中身・個人情報を外部サーバーへ送信またはディスクへ永続保存しないメモリ完結アーキテクチャを採用しており、GDPRおよび個人情報保護法に配慮した運用が可能です。

## 4. 管理者バイパス（ホワイトリスト）設定

保守作業や脆弱性診断（ペネトレーションテスト）を実施する管理者の通信を誤って欺瞞ルートへ隔離しないよう、最前段で判定ロジックをバイパスさせる設定が可能です。

* **接続元IP／CIDRホワイトリスト**：社内固定IP、庁内LAN、管理者専用VPNのIPレンジを指定することで、該当通信を無条件で正規バックエンドへ通過させます。
* **Dry-Run（監視専用）モード**：本番稼働前の検証期間中、ダミー応答を発動させず検知ログのみを記録する運用が可能です。
